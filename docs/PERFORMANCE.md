# 性能实测 · 2026-11-06

设备：AMD Ryzen 7 9700X（16 逻辑处理器），RTX 5070，Windows。所有百分比均按 16 逻辑处理器归一化为整机 CPU 百分比。

| 测试范围 | 平均整机 CPU | 平均内存 | 条件 |
|---|---:|---:|---|
| 优化前采集链路 | 0.830% | 采集进程 43.4 MiB 工作集 | 60.12 秒，20 次；含 NVIDIA 查询和反复 WMI 探测的子进程 CPU |
| 优化后采集链路 | 0.101% | 采集进程 39.3 MiB 工作集 | 60.10 秒，20 次；含 NVIDIA 查询 CPU，无反复 WMI 探测 |
| 可见 Electron 应用 | 0.068% | 344.3 MiB 私有内存；工作集合计 402.5 MiB | 预热 10 秒后测 60.41 秒；3 秒真实采样、时钟及预览更新，自动推送关闭 |
| 内置常驻采集器（未提权） | 0.074% | 94.6 MiB 私有内存；126.1 MiB 工作集 | 预热 10 秒后测 61 秒；CPU/GPU 采集，当前权限无有效 CPU 温度 |

优化后采集 CPU 开销约下降 88%。主要原因是移除每 15 秒启动 PowerShell/WMI 的探测；常驻采集器可用后，显卡也直接使用其数据，避免重复启动 nvidia-smi。

## 如何解读

- **Electron 不是 39 MB 的应用。** 39 MB 是独立测试采集脚本的内存。桌面应用的常驻私有内存约 344 MB，若另开常驻传感器进程还会增加约 95 MB。
- Electron 数据来自 `app.getAppMetrics()` 的主、渲染、GPU、utility 进程的累计 CPU 时间；不包含短命的 nvidia-smi 子进程。采样链路测试通过保留子进程句柄读取 Windows `GetProcessTimes`，计入短命查询的 CPU 时间。
- 单独测得的进程工作集相加可能重复计算共享页；私有内存更适合判断应用实际独占内存。
- 这些为不同时间窗口的测量，不能直接拼成一次精确的整机合计。按测试量级，当前 UI + NVIDIA 轮询约为 0.15–0.2% 整机 CPU，属于估算。
- 未进行游戏 FPS、GPU 引擎利用率、磁盘或 USB 实机刷新负载测试，不能据此保证任何工作负载完全无影响。
- **尚未完成管理员授权下的 CPU 温度驱动路径性能测试。** 未提权测试里温度库返回的 0°C 已被判为无效，未当成真实数据。
- UI 视觉和组件在测量后进行了进一步调整，CPU/内存结果适用于该版本的同类采样/预览路径，不是最终每个桌面布局的严格上界。

## 复现

`pnpm benchmark` 打开可见应用，预热 10 秒后测量 60 秒并自动退出，报告存入开发数据目录 `runtime/benchmark-electron.json`。

`scripts/benchmark.cjs` 测试 3 秒采样链路；先编译 `scripts/ProcessMeter.cs` 为 `out/ProcessMeter.exe`。报告位于 `out/benchmark-collector.json`。计量包装器自身的额外开销不计入生产采样成本。

`scripts/benchmark-helper.ps1` 在当前权限运行采集器，预热后测量并正常停止。报告位于 `out/benchmark-helper.json`。原始报告、机器状态、位置配置均留在本机，不上传。


## v0.2.2 内存优化复测

本次保留完整 Maple Mono NF CN 字体、真实 GPU/内存/CPU 占用采样、横屏桌面。每个界面阶段各测 30 秒，开始测量前均完成一次实际 PNG 导出，导出进程退出后再采样。CPU 温度采集器在未提权状态单独测 60.86 秒；管理员驱动路径仍待授权后验证。

| 进程范围 | 平均私有内存 | 平均工作集合计 | 平均整机 CPU |
|---|---:|---:|---:|
| 新版前台控制面板 + 后台业务 | 216.9 MiB | 342.8 MiB | 0.034% |
| 新版托盘后台，控制面板已销毁 | 101.2 MiB | 219.7 MiB | 0.019% |
| 新版原生传感器宿主，未提权 | 51.6 MiB | 70.4 MiB | 0.124% |

- 旧版前台私有内存 344.3 MiB，新版约 216.9 MiB，降低约 37%；使用托盘后台时，桌面部分相对旧版降低约 71%。
- 传感器宿主从 PowerShell 的 94.6 MiB 改为原生 CLR 程序的约 51.6 MiB，减少约 45%。两次 CPU 用量不同，不据此宣称原生宿主更省 CPU。
- 前台与后台阶段在同一次运行中测量；旧版对比与传感器测量属于独立时间窗口，数字不是严格的同机同时合计或所有负载的上限。
- 托盘后台没有保留 Tab 渲染进程。采集继续运行，模拟定时 USB 推送、恢复控制面板、双方向排版均已通过集成检查；没有用裁剪工作集的方式掩盖内存占用。
- 关闭界面硬件加速降低 GPU 进程占用；PNG 由短命 utility 进程导出，字体与栅格化分配随进程退出释放。这会增加每次导出的进程启动开销，以换取更低的常驻内存。
- 上表不包含 PNG 导出时临时进程的峰值，也不包含真实 USB/SSH 设备负载。任务管理器采用的内存列可能与私有提交量不同，工作集也一并列出，避免混淆。

运行 `pnpm benchmark:memory` 复现前台 → 托盘后台 → 恢复界面的测量，原始报告在 `runtime/benchmark-memory.json`。运行 `scripts/benchmark-helper.ps1` 测试原生宿主，报告在 `out/benchmark-helper-native.json`。旧 PowerShell 宿主已经移除，上述旧版数值仅保留为历史测量记录。

实现参考：[Electron 硬件加速与进程指标](https://www.electronjs.org/docs/latest/api/app)、[临时 utilityProcess](https://www.electronjs.org/docs/latest/api/utility-process)。
